# v79「定点坐标篡改」诊断件（2026-10-28 15:30）

## 为什么换方案

v78 把视口从 2048×2048 钳到 2560×1440，**引擎的 UI 布局是死绑视口尺寸的** →
钳制导致主界面一半不显示。**视口钳制方案废弃。**

v79 回到 v71 的思路但去掉危险动作：**不重画、不跳过原函数**，只把**那一个越界面片**的
y 坐标改掉，让引擎自己画。

## v79 规则（极苛，宁可漏改不可误伤）

| 项 | 规则 |
|---|---|
| 拦截路径 | DIP(vt82) / DP(vt81) / UP(vt83) / DIPUP(vt84) 四路 |
| 触发条件 | 顶点**恰为 4 个**，且这 4 个顶点的 y **全部 > 窗口高(bbH)**（正常 UI 绝不可能整块在窗口外） |
| 修正方式 | UP / DIPUP：顶点在用户内存 → **复制副本** → 改副本 y → 把副本传给原函数<br>DP / DIP：顶点在 VB → `Lock` 写入 → 改 y → `Unlock` → **引擎自己画** |
| 缩放 | `y' = y × bbH / vpH`（vpH = 引擎视口高，**只记录不改**），clamp 到 `[0, bbH]` |
| 绝不做 | **不调用 DrawPrimitiveUP 重画、不 return 跳过原函数**（v72 红三角的根因） |
| 限流 | 每帧最多修正 8 次 |
| 开关 | `O2_NO_V79=0` 一键关闭 |

> 源级核验：v79 二进制里 **没有任何 `DrawPrimitiveUP` 调用**（`grep` 零命中）。

## 用法

1. 先把正式版装回去（当前正式位 = V1.03.2 用户版）：
   - `..\..\Obscure2_汉化补丁_V1.03.2.exe`，或手动复制 `..\d3d9.dll`
     （方案A 用 `..\方案A_寒蝉端黑体\d3d9.dll`）；
2. 要测 v79：把 `d3d9_v79_方案A.dll`（或方案B）**改名成 `d3d9.dll`** 放进游戏目录；
   或直接跑 `..\..\Obscure2_汉化补丁_V1.03.3_v79定点修正.exe`；
3. 进 2K 浴室场景 → 退出 → 收回日志。

## 看哪几行

| 行 | 含义 |
|---|---|
| `[INIT] ===== V79_PROD 定点坐标篡改(不重画不改视口) =====` | 版本对 |
| `[V79] 定点坐标篡改 = 启用（O2_NO_V79=0 关闭）` | 功能开 |
| `[V79] 视口高 = 2048（窗口高 1440，仅记录不改）` | 拿到缩放基准 |
| **`[V79] UP/DIPUP/DP/DIP 越界面片坐标修正 #1 yCol=N scale=703/1000 (bb=2560x1440 vp=2048)`** | **命中并修正了**（yCol=命中的列号，scale=1440/2048） |
| `[V73] UP/DIP/DIPUP/DP … v0: …` | 各路径的顶点坐标（定点数），可核对哪一路画的那张贴图 |

**若没有任何 `[V79] 越界面片坐标修正` 行** → 说明那 4 顶点面片的 y 不是"全部 > 窗口高"
（可能只有部分越界，或它根本不是 4 顶点）→ 把 `[V73]` 的坐标行发我，我按实测特征收紧判据。
