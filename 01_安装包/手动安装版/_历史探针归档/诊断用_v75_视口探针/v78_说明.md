# v78 视口钳制版 · 装完看哪几行（2026-10-28 15:22）

## 前提（你刚更正的关键事实）

另一台正常显示的机器是 **A 卡(AMD)**，本机是 **N 卡(NVIDIA)**。
N 卡驱动对**超出窗口边界的顶点**做严格裁剪，A 卡可能带容错 →
引擎在 2560×1440 窗口里自设 2048×2048 视口、把提示贴图面片算到 y≈1950（> 窗口高 1440）时，
**N 卡裁掉、A 卡容错显示** —— 这就是两台机器表现不同的唯一原因。

## v78 做了什么（单变量）

Hook `IDirect3DDevice9::SetViewport` (vt47)：若 `pViewport->Height` **大于后备缓冲高度**
（2048 > 1440），**强制改成后备缓冲高度**再调原函数。
其它保持 v76：options.xml 分辨率解析修复（引号 bug）、阈值 9、无任何重画、只读探针。

开关：`O2_VP_FIX=0` 可一键关闭钳制（设环境变量后启动游戏）。

## 钳制之后还要看一件事

`[V73] UP/DIP/DIPUP … v0: …`（定点数坐标）——
**如果 UI 顶点的 y 从 ≈1950 变成了 ≈1370**（=1950×1440/2048），
说明引擎按新视口重排了 UI → **贴图必然回来了**；
**如果 y 仍是 ≈1950**，说明引擎只在初始化时算了一次 UI 比例、钳制视口对它无效 →
那就走你说的「备用逻辑」：在 DP/UP 的 4 顶点面片上强制修正 y（v79）。

## 副作用预告

视口从 2048×2048 变成 2560×1440 后，**3D 场景的渲染区域会变**（底部 608px 不再由 3D 场景绘制，
HUD/UI 会按新视口重排）。如果出现画面比例异常，把 `[V75] SetViewport #N …` 发我，
我可以改成"只钳制 UI 绘制阶段"或改用别的等效做法。
