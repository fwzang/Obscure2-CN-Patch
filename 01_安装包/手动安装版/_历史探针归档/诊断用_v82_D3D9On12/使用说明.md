# v82 · D3D9On12 测试（2026-10-28 20:30）

## 为什么这条路和前面都不一样

前面试过的 DXVK / dgVoodoo2 都是**第三方**转译层（D3D9 → Vulkan / D3D9 → D3D11），
而 D3D9On12 是**微软官方**的实现：D3D9 API 直接由 D3D12 驱动栈执行。
如果贴图在 On12 下恢复，说明问题出在 **N 卡自己的 D3D9 用户态驱动（UMD）路径**上，
而 D3D12 路径是好的。

## 已核实的三件事（都在本机验证过）

| # | 事实 | 证据 |
|---|---|---|
| 1 | `SysWOW64\d3d9on12.dll` **不能**改名当 d3d9.dll 用 | 它只导出 3 个 **DDI 驱动接口**（`OpenAdapter` / `GetPrivateDDITable` / `SetAppCompatData`），**没有 `Direct3DCreate9`** —— 游戏唯一导入函数缺失 = 启动即崩 |
| 2 | 正确入口在系统 `d3d9.dll` 里 | `SysWOW64\d3d9.dll` 的 17 个导出中含 **`Direct3DCreate9On12`** 与 **`Direct3DCreate9On12Ex`** |
| 3 | **本机 D3D9On12 真实可用** | `probe_on12.exe` 实测：`Direct3DCreate9On12 → obj` 非空，`CreateDevice(HAL) hr=0x00000000`，caps `MaxTex=16384x16384 PS=3.0 VS=3.0`，与经典 D3D9 完全一致 |

所以不需要 DxWrapper、不需要外网下载：**我们的汉化代理本身就是 d3d9.dll，
天然就是那个"调用方"** —— 开关一开就切到 On12，而且**与汉化天然共存**。

## v82 改了什么（单变量）

`Direct3DCreate9` 的取库路径，多了一个分支：

```
if (O2_D3D9ON12=1 && 系统 d3d9.dll 导出 Direct3DCreate9On12)
        -> Direct3DCreate9On12(sdk, NULL, 0)      // D3D9 走 D3D12 后端
else    -> 原样 Direct3DCreate9(sdk)              // 行为与 V1.03.2 完全相同
```

- **默认关闭** → 同一份 DLL 既可当正式版（不设环境变量，行为零变化），也可一键测 On12
- On12 返回 NULL 时**自动回落到普通路径**，不会让游戏启动失败
- 顺带补上了一个缺失的开关：`O2_NO_V79=0` 可关闭 v79 的坐标篡改
  （此前 `g_v79On` 默认开但**没有任何环境变量入口**，无法做干净的单变量测试）

| 文件 | md5 | 大小 |
|---|---|---|
| `d3d9_v82_on12_方案A.dll` | `e1b360fbfb1ed4354e3cbeeb3f2e246a` | 944,294 B |

两个 DLL 均 17 导出 / i386 / `Direct3DCreate9` 在列（PASS），图集原样未动。

## 第一轮怎么测（纯 On12，不含汉化）

游戏目录当前状态：**只有 v82 代理 + 原版数据包**（无 DXVK / dgVoodoo 残留）。

双击 `T1_On12_vanilla.bat`（它会设好环境变量并从游戏目录启动游戏）：

```
O2_D3D9ON12=1     ← 切到 D3D12 后端
O2_NO_SWAP=1      ← 关字体替换（画面保持纯英文，排除中文图集干扰）
O2_NO_V79=0       ← 关坐标篡改（排除几何修改干扰）
```

### 判读（先看日志，再看画面）

`<游戏目录>\d3d9proxy.log` 里：

```
[ON12] D3D9On12 开关 = 开 -> Direct3DCreate9On12
[ON12] Direct3DCreate9On12 sdk=32 -> obj=0x........  （D3D9 已走 D3D12 后端）   ← 生效
[D3DC9] sdk=32 obj=0x........ vt=0x........ (...) on12=1
```

| 日志 | 画面 | 结论 |
|---|---|---|
| 有 `on12=1` | 浴室贴图**出现** | ✅ **根因 = N 卡 D3D9 UMD 路径** → 立刻做完整版（On12 + 汉化） |
| 有 `on12=1` | 贴图仍**不显示** | On12 也救不了 → 不是 D3D9 路径问题，收工发版 |
| `returned NULL` / `not exported` | 无变化 | On12 没接上（本机已证明可用，出现此情况请把日志发我） |
| 游戏起不来 / 花屏 | — | 跑 `R_restore_plain.bat` 回纯原版，把日志发我 |

## 若第一轮成功：第二轮（On12 + 汉化）

1. 恢复汉化数据包（方案A fullA，`datapack.hvp` = `e657e90d…`）
2. 用 v82 方案A 代理，环境变量只留 `O2_D3D9ON12=1`（**不要**设 `O2_NO_SWAP`，即开启字体替换）
3. 进浴室同时验证：**贴图在 + 中文正常** → 这就是最终形态

届时把 `O2_D3D9ON12=1` 写进启动器（或在代理里翻成默认值），安装器一并带上。
