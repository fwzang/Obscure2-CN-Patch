# v73 纯只读探针 · 使用说明（2026-10-28 19:50）

## 为什么有这一版

v70 / v71 / v72 尝试用「Lock 读顶点 → 改 y → DrawPrimitiveUP 重画」把 2K 下被引擎
裁到屏幕外的提示贴图拉回屏内。**实机结果：红三角色块（误伤正常几何），且贴图仍不显示。**
→ 该路线（写顶点 / 重画）**已全部废弃**。

本版回到 **V1.03.3 保底版**（提升阈值 9 + 目标分辨率自适应，**不含任何重画**），
只加**纯只读探针**：不改任何顶点、不跳过任何绘制、不改任何绑定。

## 探针怎么用

1. 备份当前 `d3d9.dll`；
2. 把探针版**改名成 `d3d9.dll`** 放进游戏目录（方案A 用方案A那份）；
3. 启动游戏 → **进浴室场景**（贴图不显示的那个场景）→ 停留几秒 → 退出；
4. 收回 `<游戏目录>\d3d9proxy.log`，把**所有含 `[V73]` 的行**发回；
5. 测完把保底版 `d3d9.dll` 放回去（或用 `restore.bat`）。

## 探针会打印什么

```
[V73] UP stage0tex=0F8231E0 512x256        ← 画这一笔时 stage0 绑的是哪张纹理、多大
[V73] UP pt=5 primCount=2 stride=36 nVert=6 ← 图元类型/顶点数/步长
[V73] UP v0:  12.34  1182.00  …            ← 每个顶点的全部坐标（定点数，每顶点一行）
[V73] DIP stage0tex=… / [V73] DP … / [V73] DIPUP …
```

四条路径都会打：**DIP**(vt82) / **DP**(vt81) / **UP**(vt83) / **DIPUP**(vt84)。
坐标是定点数（`%c%ld.%02ld`），**不使用浮点格式**（`wsprintfA` 不支持 `%f`，
用了会被打成 `f` 并截断后面的内容——这是 v70/v71 探针连续失效的原因）。

## 拿到日志我们要判断什么

1. 浴室提示贴图**到底由哪条路径画**（UP 最可能：顶点直接在内存里）；
2. 那一笔绑定的 stage0 纹理是**原版贴图**还是**我们的中文图集**（若是后者 → 是误替换，
   方向完全不同）；
3. 顶点坐标里 **y 到底多大**（是否真的 > 窗口高 1440）；
4. 若日志里**一条 `[V73]` 都没有** → 这张贴图根本不经过 D3D9 的这四个绘制函数
   （可能走引擎的特殊层或用贴图矩阵绘制）→ 需要换思路（查引擎源码 / 查资源里的贴图尺寸）。

## 安全保证

- 探针只 `Get`/`Lock(READONLY)`/`Unlock`，**不写任何顶点**；
- 不调用 `DrawPrimitiveUP` 重画，不 `return` 跳过任何绘制；
- Lock/Unlock 严格成对；读失败即跳过打印；
- 探针版本与保底版的差异**只有探针代码**（源码层面：`v70_repaint` 函数保留但零调用）。
