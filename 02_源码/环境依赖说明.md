# 环境依赖说明（构建 / 复现必备）

> 本文件记录 V1.04 交付包各组件的**实测版本号**与**可逐字节复现的编译命令**。
> 换新电脑照抄即可，无需再猜参数。

## 0. 一句话总览

- 编 `d3d9.dll`（32 位）：**w64devkit 的 `i686-w64-mingw32-gcc` 16.2.0**
- 跑图像/图集脚本：**Python 3.13 + Pillow 13.0.0（+ fontTools 4.67.0）**
- 打 `datapack.hvp`：**obscure-hvp 1.5.1**（已随包：`02_源码/产线工具/obscure-hvp.exe`）

## 2. 逐字节复现 V1.04 发布版（v69）的命令（已实测通过）

**推荐方式**（自动处理文件名/参数，一条命令）：

```bat
python 00_工具中台\02_构建脚本\build_from_package.py
```

手动等价命令（注意：源码文件名会进 COFF 符号表，**必须先复制为 `d3d9_proxy_v69.c`**）：

```bat
cd 05_hook源码与译文\d3d9proxy_src
copy d3d9_proxy.c d3d9_proxy_v69.c
..\..\00_工具中台\01_编译链\w64devkit\bin\i686-w64-mingw32-gcc.exe -O2 -fno-sanitize=undefined -shared ^
   -DFORCE_POINT_SAMPLER=0 -DPRESENT_RESTORE=0 -Wl,--image-base=0x6BE00000 ^
   -o d3d9_v69.dll d3d9_proxy_v69.c d3d9.def
```

**结果 md5 = `b42417bd2a51ff5d95d3a84970b8a20f`**（与 V1.04 发布版逐字节一致，903,272 B）。

前提条件：
1. `atlas_png.h` 由 `gen_atlas_header.py` 从 **`04_基线与回滚/g3_atlas.png`（md5 `e172a188…`）**生成
   （脚本默认读 `../_work/g4/g3_atlas.png`，在交付包里请先把基线图集放到该路径，或改脚本 SRC）；
2. 工作目录为 `d3d9proxy_src`（`d3d9.def` 必须在场，漏了会导出全部符号）。

三个**缺一不可**的参数及原因：

| 参数 | 原因 |
|---|---|
| `-DFORCE_POINT_SAMPLER=0` | 源码默认 `1`＝强制点采样，漏传则字体边缘发糊（V1.01/V1.02 回归事故的根因） |
| `-DPRESENT_RESTORE=0` | V1.02 起关闭帧末还原（减少呈现路径干预） |
| `-Wl,--image-base=0x6BE00000` | ld 的 auto-image-base 会**按输出文件名哈希**定 ImageBase，不钉住就无法复现（实测同名不同路径也会变） |

> 换一个 GCC 版本仍可编译出**功能一致**的 DLL，但逐字节 md5 会变；
> 需要 md5 一致的复刻，请用 GCC 16.2.0。

诊断版（只写日志、不替换纹理）：把 `-o d3d9_v69.dll` 换成 `-o d3d9_diag.dll` 并加 `-DG3_DIAG=1`。

## 3. 一键脚本

`05_hook源码与译文/d3d9proxy_src/build.bat`——生成图集头 → 编诊断版 → 编生产版 → 校验导出表。
注意它是**留档脚本**：编译用的是 `d3d9_proxy.c` 原名，产物功能相同但 md5 与发布版不同
（差 `STT_FILE` 一项）。**逐字节复现请用 `00_工具中台/02_构建脚本/build_from_package.py`。**

## 4. 安装器构建（可选，只有改安装器时才需要）

```bat
cd 02_源码\安装器
..\..\_toolchain\w64devkit\bin\windres.exe --codepage=65001 -O coff -i setup.rc -o setup.res
..\..\_toolchain\w64devkit\bin\gcc.exe -O2 -municode -mwindows -o setup.exe setup.c setup.res ^
    -lcomctl32 -lole32 -lshell32 -lgdi32 -luser32 -ladvapi32
python gen_info.py info_o2.txt info_o2.h
python build_installer.py
```
（或直接 `python build_all.py` 一键完成；改 `info_o2.txt` 后**必须重跑**，否则嵌入旧文案。）

## 5. 工具链获取（已随包附带）

编译器**就在包内**：`00_工具中台/01_编译链/w64devkit-2.10.1-gcc16.2.0.zip`（160.8 MB，
md5 `781b59607b1969805986de9b29a634f0`）。双击 `00_工具中台/01_编译链/解压工具链.bat`
即解压到 `00_工具中台/01_编译链/w64devkit/`，随后 `build_from_package.py` 会自动找到它。

> 解压用系统 `tar.exe`（bsdtar）。若在 Git Bash 里手动解压，注意 Git Bash 自带的 GNU tar
> **不认 zip**，需显式调用 `C:\Windows\System32\tar.exe`。
> 解压出的 `w64devkit/` 约 700 MB，属于构建临时产物，可随时删除（zip 保留即可）。

## 6. Python 依赖安装

```bat
python -m pip install pillow==13.0.0 fonttools==4.67.0 jieba==0.42.1
```
最低可用版本：Python ≥ 3.10、Pillow ≥ 10、fontTools ≥ 4.40。
注：`fix_break_words.py`（断句检查）才需要 jieba，日常改字/打包不需要。

```bat

certutil -hashfile d3d9.dll MD5            :: 应为 b42417bd2a51ff5d95d3a84970b8a20f
:: 2) 导出表
python 02_源码\产线工具\check_exports.py d3d9.dll
:: 3) 图集/def/DLL 三者一致（打包前强制关卡）
python 02_源码\产线工具\verify_pack.py
```
