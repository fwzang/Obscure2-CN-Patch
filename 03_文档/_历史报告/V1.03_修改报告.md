- **版本**：V1.03
- **基线**：V1.02
- **日期**：2026-10-25
- **适用**：Steam 版 Obscure II（AppID 254480）
- **数据包**：**未变更**（full18 / fullA 与 V1.01 逐字节一致）

---

## 一、本版修什么

**部分场景的 UI / 提示贴图被误替换成中文字库**（表现为该贴图不显示，或显示成文字碎片）。

### 根因

字体识别用的是「尺寸 + 格式」判据：

```c
w == 512 && h == 256 && fmt == A8R8G8B8   → 当作字体，替换成中文图集
```

但游戏里同规格的纹理**远不止字体**——UI 图、提示图、图标都可能正好是 512×256。
实测一局日志里，有 **17~22 个** 512×256 纹理被登记为「字体」，全部被换成了中文图集。
被换掉的那些图，画面上自然就"没图了"。

### 修法：严格字体判定

字体图集有一条独一无二的上传路径（二代实测确认）：

```
UpdateTexture: src(512×256, SYSTEMMEM pool=2) → dst(512×256, DEFAULT pool=0)
```

V1.03 只在 `UpdateTexture` 里把**这个 dst** 记入「严格集」，
`SetTexture` 时**只有严格集里的纹理才替换**。其余同规格图片原样保留。

| 项 | 行为 |
|---|---|
| 兜底 | 严格集为空（该机器走了别的上传路径）→ 自动退回旧判据，保证中文不丢 |
| 开关 | `O2_STRICT_FONT=0` 强制走旧判据（对照用） |
| 日志 | `[FSTRICT]` 记录确认/跳过，一眼看出判定走了哪条路 |
| 代价 | 不读顶点、不加 Lock、不增加每帧开销（只在 UpdateTexture 里多一次 GetLevelDesc） |

### 与 V1.02 的关系

**V1.02 的所有修复原样保留**，未做任何回退：

- 强制窗口化（修 Alt+Tab 卡死）
- `WS_EX_APPWINDOW` + 清 TOPMOST（修窗口永远置顶）
- 看门狗 `[WD]`、设备丢失守卫、`PRESENT_RESTORE=0`

## 二、关于「安装包里 DLL 是旧版」的核查

用户在新电脑上反馈「贴图没效果」，怀疑包内 DLL 是旧版、硬编码 800×600。逐项核查结果：

| 说法 | 核查结果 |
|---|---|
| 包内 `d3d9.dll` 是旧版 | **不成立**。V1.02 包内是 `c333e317…`，即 v66 构建产物，含窗口化与看门狗 |
| 硬编码 800×600 | **不成立**。源码与二进制中均无 800×600；窗口尺寸取自 `pp->BackBufferWidth/Height`，随分辨率动态 |
| 缺「尺寸二次校验」导致误判 | **部分成立**。二次校验（绑定前查尺寸）一直存在，但它只能挡住"指针复用"，挡不住"本来就同规格的非字体纹理"。这正是本版要解决的 |

结论：不是装错版本，而是**误判逻辑本身还没修**。V1.02 能在我这台机器上正常，
是因为那一局的 512×256 纹理恰好没有覆盖到关键贴图；换一台机器、换一个场景就会暴露。

## 四、验证清单（新电脑上照这个走）

1. 安装完成后，确认 `d3d9.dll` 的 md5 是 `5967d334…`（方案B）
2. 启动游戏，日志第一行应出现：

   ```
   [INIT] ===== V67_PROD 严格字体判定版 =====
   [FSTRICT] 严格字体判定 启用（O2_STRICT_FONT=0 关闭）
   [FSTRICT] #1 确认字体 dst=0x...（严格集=1）
   ```

3. 进浴室，确认提示贴图正常显示
4. Alt+Tab 来回切 10 次以上，确认不卡、窗口层级正常
5. 若某处贴图**仍**异常：
   - 先跑 `O2_NO_SWAP=1` 对照：贴图回来 = 仍被替换（把日志发来，看 `[FSTRICT]` 走了哪条路）
   - 贴图没回来 = 与替换无关，往渲染路径查

## 五、已知限制

1. **严格集依赖 UpdateTexture 上传路径**。若某台机器上字体走的是别的路径
   （比如 CreateTexture 直接带初始数据），严格集会是空的，此时自动退回旧判据，
   表现为"和 V1.02 一样"。日志里 `[FSTRICT] 严格集=0` 就是这个状态。
2. **4K 仍未实测**。窗口化与分辨率无关，稳定性应无碍；但界面放大倍率更高，
   清晰度与个别贴图表现没有数据。
3. **启动偶发 `0xC0000005 @ ckpt=init`**（设备创建前），疑似 Steam overlay 注入竞态，
   与本补丁逻辑无关，重开即可。
