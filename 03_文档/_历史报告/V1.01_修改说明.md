# V1.01 修改说明（2026-10-22）

V1.01 是当前发布基线：在 V1.00（V1.02 安装器逻辑 + 三处修改 + v49 字体修复）基础上，
**新增「两套字体方案选择」**。本文记录全部变更与验证证据。

## 一、V1.01 新增：安装器双方案选择

游戏把 540p 设计分辨率的 UI 拉伸到 1440p 显示（实测放大系数 k≈2.8），单个汉字的
屏幕 advance ≈42px 而图集只有 19px 信息量——这是引擎渲染路径决定的数学必然，
不是采样参数问题（详见 `03_文档/汉化补丁V1.00_总结与流程报告.md` 与 KNOW 限制）。
在不动 hook 的前提下，V1.01 从**生成侧**提供两套字形，让玩家按观感自选：

| 方案 | 字体 | 渲染 | 数据包 | 字体代理 |
|---|---|---|---|---|
| **B（默认）** | 寒蝉活楷体 | SSAA=3 + BOX | full18（`d25123d2…`） | v49（`47060c4b…`） |
| **A** | 寒蝉端黑体 Bold | SSAA=3 + BOX | fullA（`e657e90d…`） | 黑体图集版（`0e504ff0…`） |

- 安装器新增「字体方案」单选（默认 B），安装时自动选择对应差分与字体代理；
- 载荷由 4 条扩为 6 条（8 槽内）：`datapack.delta` / `d3d9.dll` / `datapack_a.delta` / `d3d9_a.dll` / `dinput8.dll` / `main.patch`；
- 新增隐藏自测入口：`/testA:<目录>` 静默安装方案 A（原 `/test:` 走方案 B）。

**为什么 A 要换数据包、B 不用**：中文图集像素只存在于 `d3d9.dll`（hook 运行时替换显存纹理），
datapack 里只有 def（字形坐标/宽高）。黑体的字形度量与活楷不同（ASCII advance、墨框），
def 必须按新度量重新生成；方案 B 渲染参数不变 → def 与 V1.00 **逐字节一致**（md5 同为
`08ac3869…`），数据包就是 full18 本体。

## 二、V1.00 既有三处修改（沿用）

1. **"加入游戏"断行**：开场提示 `…按回车键加入\n游戏，并接管…` →
   `…加入游戏，\n并接管…`（语料第 2532 行；行宽 17→19 ≤24；记录字节数不变）
2. **删除安装器信息面板的更新说明**（用户自改 `info_o2.txt`；构建时必须重跑 `gen_info.py`）
3. **版本号重置**：V1.01 起为 `1.0.1.0` / `OriginalFilename Obscure2_HanHua_V101.exe`

## 三、随基线保留的字体修复（v49）

v48 编译时漏传 `-DFORCE_POINT_SAMPLER=0`（源码默认 1=点采样），叠加 UI 放大后边缘发糊；
v49 显式传回，采样交还引擎默认（双线性）。V1.01 两套方案均基于该修复后的源码构建。

## 五、验证记录

- **双方案静默安装**：`/test`（B）rc=0 → 落盘 `d25123d2`+`47060c4b`；
  `/testA`（A）rc=0 → 落盘 `e657e90d`+`0e504ff0`；两次均无杂散文件
- **版本资源**：`1.0.1.0` / `V1.01` / `Obscure2_HanHua_V101.exe` 均确认写入二进制
- **差分闭环**：原版 + 各自 delta 重建 = full18 / fullA 逐字节一致
- **工具链**：基线图集对照构建与出厂 v49 **逐字节一致**（`47060c4b`，
  需 `-Wl,--image-base=0x6BE00000` 钉住 ld 的 auto-image-base 文件名哈希）；
  两套测试 DLL 与 v49 的反汇编指令流仅差图集长度立即数
- **完整技术细节**：见 `03_文档/字体方案AB_生成与验证报告.md`

## 六、升级路径提醒

- 从 **V1.00/V1.02** 升 V1.01：安装器会校验数据包，若当前是汉化态（非原版）会报 **-15**，
  请先「还原原版」再安装（或直接用手动安装版覆盖）。
- **切换字体方案**：同样先「还原原版」，再装一次并选另一方案（差分只认原版数据包）。
- 已装 V1.01 的玩家重装 V1.01：数据包已是汉化版时会跳过重建，直接替换字体代理。
