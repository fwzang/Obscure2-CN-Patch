## 一、修了什么

### 1. 贴图误杀（2K 下消失的贴图）

**实测证据（2026-10-28，2560×1440，V69_PROD 阈值=1 的一局）**：
本局被"提升"为字体的 10 个 512×256 纹理中，只有 1 个是真字库，其余 9 个是一次性 UI/提示贴图。

| 纹理 | 日志出现次数 | 性质 |
|---|---|---|
| `0F539580` | **126 次** | 真字库（每帧绑定） |
| 其余 9 个 | **2–8 次** | 一次性贴图 → 被误提升 → 被替换成中文图集 → **贴图消失** |

**修法**：提升阈值 `1` → **`9`**（> 实测贴图最高绑定次数 8）。
贴图全部保住；真字库 126 次仍在第 9 次绑定时提升，几乎无延迟，文字与启动观感不变。
`O2_PROMOTE_N` 环境变量仍可覆盖（`0` = 关闭提升）。

> 二进制已核验：`.data` 段 `g_promoteN` 初值 = `09 00 00 00`。

### 2. 分辨率（发糊 / 二次低分辨率拉伸）

**事实澄清**：源码原本**没有**写死 800×600 —— 它读的是 `pp->BackBufferWidth/Height`；
日志里那个 800×600 是**引擎自己传给 CreateDevice 的值**（尽管 `options.xml` 里是 2K = 167773600）。
所以"引擎给 800×600 → 窗口按 800×600 建立 → 拉伸铺满 2K 屏"就是多一次低分辨率渲染 + 拉伸的来源。

**修法**：强制窗口化时，后备缓冲改用【目标分辨率】建立，优先级：

1. `O2_WIN_SIZE=WxH` 环境变量（显式指定）
2. `options.xml` 的 `VideoResolution`（`(v>>16)&0xFFFF` = 宽，`v&0xFFFF` = 高）—— 尊重玩家在游戏里设的分辨率
3. 当前显示器分辨率（`EnumDisplaySettings`）
4. 都不行才沿用引擎原值

目标分辨率与引擎请求的宽高比不一致时，按目标宽等比换算高度（不改变 UI 布局比例）。

## 六、v71 修正（2026-10-28 19:35，依据实机日志）

**实机日志**（V70_PROD，2560×1440 窗口）：

```
[V70] probe stride=36 yOff=4 vp=2048x2048  v0=f/f/f/f ...
```

**两处判定错误**：

1. **边界用错**：视口是 2048×2048，但**窗口/后备缓冲只有 2560×1440**。引擎把面片算到
   y≈1950 —— 在 2048 视口内，却在 1440 窗口外被裁掉。v70 拿**视口高**当边界 → 永远判不出
   越界 → 从不重画。v71 改用 `bound = min(视口高, 后备缓冲高)`。
2. **y 偏移猜错**：stride=36（9 个 float），引擎是自定义 FVC 0x144，y 不一定在 offset 4。
   v71 改为**自动探测 y 列**：逐列检查"4 个值是否整体落在边界外"，命中即认定该列是 y，
   并只缩放该列；探针同时把全部 9 列以**定点数**逐顶点打印（`wsprintfA` 不支持 `%f`，
   v70 探针的数值全被打成 `f`，故无法核对）。

**附带确认**：实机每局只有 **1 次**「4 顶点 / 2 三角形」DIP —— 就是那张提示贴图本身，
拦截窗口极窄，v71 必须一次判准。

**v71 指纹**：方案B `d3d9.dll` 909,098 B / `3d2dbefd7e38d1f77250d28041e3b4b2`；
方案A `d3d9_a.dll` 935,722 B / `b5770c53d281ad9ed69d09695b56efea`；
安装包 `Obscure2_汉化补丁_V1.03.3.exe` 3,644,209 B / `0059eeef36c0539fff202ef88bd8f7c4`。

## 七、v72 修正（2026-10-28 19:40，依据 v71 实机日志）

**v71 实机日志**（4 局各 1 次 probe，但顶点数值全丢）：

```
[V71] probe stride=36 cols=9 vp=2048x2048 bb=2560x1440 bound=f
```

**三个问题**：

1. **探针数值丢失**：`bound=%.0f` 里的浮点格式让 `wsprintfA` 中断，后面的 `%s`（顶点数值）
   整段没写出来 → 无法核对 y 在哪一列。v72 把浮点全部整数化（`%c%ld.%02ld` 定点数），
   顶点逐行单独打印。
2. **覆盖路径不足**：v71 只拦 DIP，而实机每局仅 1 次「4v/2t DIP」（日志里满屏 `prim=144`
   的 3D 几何），提示贴图未必走 DIP。v72 扩展为**四路**：
   - `vt83 DrawPrimitiveUP` —— 顶点直接在用户内存，**就地修正后照常绘制**（画面连续，最安全）
   - `vt81 DrawPrimitive` —— 顶点在顶点缓冲 → 修正后用 DrawPrimitiveUP 重画
   - `vt84 DrawIndexedPrimitiveUP` —— 顶点+索引都在用户内存 → 展开后修正重画
   - `vt82 DrawIndexedPrimitive` —— 保持 v71 逻辑
3. **判定放宽**：顶点数 3~8 均参与检测；列判定沿用「整列越界」（4 个值整体落在边界外）。

**v72 指纹**：方案B `d3d9.dll` 913,326 B / `0f4d922706069cd86be39db67b360f57`；
方案A `d3d9_a.dll` 936,097 B / `b56e24928088d38b169b5830875db725`；
安装包 3,652,153 B / `43fc582beab9db5952e87f0407a5f92d`。

## 十一、v76：分辨率解析 bug 修复（2026-10-28 15:08）★ 根因

**决定性证据链**：

1. `options.xml` 里 `VideoResolution value="125830200"` → `(1920<<16)|1080` = **1920×1080**，
   **玩家的设置是对的**；
2. 但日志显示代理每次都打印 `[WIN] 目标分辨率 = 显示器 2560x1440` → **options.xml 解析失败**；
3. **解析失败的机制**：值写作 `value="125830200"`（**带引号**），而 `strtol()` 遇到 `"`
   立即返回 0 → 判定"非法" → 回落显示器分辨率。
   （`167773600` 那次能读到，是因为当时该值恰好被解析成合法值；一旦玩家改成别的
   带引号格式的值，或解析函数先匹配引号，就会静默回落。）

**后果链**：玩家分辨率设置被忽略 → 引擎 pp=2560×1440 → 引擎自设视口 2048×2048
→ **视口高度(2048) > 窗口高度(1440)** → 底部 30% 的 UI（含浴室提示贴图 y≈1950）
被窗口裁掉 → 贴图不显示。

**这也解释了所有对照现象**：
- 「1080p 依然不显示」→ **那次实验其实无效**：options.xml 是 15:06 之后才改成 1080p 的，
  而第 6 局跑在 15:06，代理仍回落显示器 → 引擎还是 2560×1440；
- 「另一台电脑正常」→ 那台机器引擎拿到的是 800×600（10-25 日志）→ 视口=窗口 → 不裁；
- 「v62 时代正常」→ 同理，v62 只做 `Windowed=TRUE`，**不碰 pp 尺寸**，引擎保持 800×600。

**v76 修法（单变量）**：目标分辨率优先级 = ① `O2_WIN_SIZE` ② **options.xml（修引号解析）**
③ 显示器分辨率；并打印完整读取诊断（路径/是否存在/原始值/解析值/最终采用值）。
其余保持：阈值 9、无任何重画、视口与四路绘制只读探针。

## 十二、v78：SetViewport 高度钳制（2026-10-28 15:22）★ N 卡裁剪对策

**决定性更正（用户提供）**：另一台正常显示的机器是 **A 卡(AMD)**，本机是 **N 卡(NVIDIA)**。
N 卡驱动对**超出窗口边界的顶点**执行严格裁剪（Clipping），A 卡可能带容错 →
同一引擎在两台机器上表现不同，这就是「重装后 2K 贴图不显示 / 另一台正常」的全部原因。
（也顺带解释了 1080p 为什么不显示：options.xml 解析失败 → 一直跑在 2K → 视口 2048 > 窗口 1440。）

**v78 修法（单变量）**：Hook `IDirect3DDevice9::SetViewport` (vt47)，
若 `pViewport->Height` **大于后备缓冲高度**（引擎自设 2048 > 窗口 1440），
**强制 Height = BackBuffer 高度**后再调原函数。
开关：`O2_VP_FIX=0` 可一键关闭。
其余保持 v76：options.xml 分辨率解析修复（引号 bug）、阈值 9、无任何重画、只读探针。

## 十三、v79「定点坐标篡改」（2026-10-28 15:30）+ 正式位回滚

**v78 失败复盘**：把视口从 2048×2048 钳到 2560×1440 → **引擎 UI 布局死绑视口尺寸** →
主界面一半不显示 → **视口钳制方案废弃**（v79 只记录视口高，不改）。

**v79 规则（极苛，宁可漏改不可误伤）**：
- 拦截 DIP(vt82) / DP(vt81) / UP(vt83) / DIPUP(vt84) 四路；
- 触发：顶点**恰 4 个** 且 4 个 y **全部 > 窗口高(bbH)**（正常 UI 不可能整块在窗口外）；
- UP/DIPUP：顶点在用户内存 → **复制副本** → 改副本 y → 传副本给原函数；
  DP/DIP：顶点在 VB → `Lock` 写入 → 改 y → `Unlock` → **引擎自己画**；
- 缩放 `y' = y × bbH / vpH`（vpH 只记录），clamp `[0, bbH]`；每帧限 8 次；
- **绝不 DrawPrimitiveUP 重画、绝不跳过原函数**（v72 红三角的根因）。
  源级核验：v79 二进制里 `DrawPrimitiveUP` 调用 **零命中**。

### 一个重要纠正
DXVK **v2.x 没有 `dxvk.deviceIndex` 这个键**（二进制里只有 `dxvk.deviceFilter` / `dxvk.hideIntegratedGraphics`；
`DXVK_DEVICE_INDEX` 环境变量也已移除）。切显卡的正确写法：
```
dxvk.deviceFilter = AMD      ; 或 = NVIDIA
```

### v80「套娃」版（已编译，默认关闭，零风险）
链式代理：**游戏 → 我们的 d3d9.dll（hook 在此）→ d3d9_dxvk.dll（DXVK）→ Vulkan → N 卡**
