## 一、修了什么

### 1. 启动瞬间一闪而过的乱码（本版核心）

**现象**：V1.03.1 装好后文字是对的，但刚进游戏时有一闪而过的乱码，随后自动恢复。

**原因**：V1.03.1 的字体识别靠「同一张贴图在 stage0 被绑定 ≥20 次」才提升，
前 20 帧仍用原版字形渲染 —— 这就是那一闪。

**修法**：

| 改动 | 说明 |
|---|---|
| 提升阈值 `20` → **`1`** | stage0 首次绑定即提升，闪现消失 |
| 新增 **`stage == 0` 门槛** | 只有 stage0 才可能是字体图集，其它 stage 一律不碰 |
| 严格集（UpdateTexture 确认过的）不受 stage 限制 | 保持既有确认逻辑 |

> 第二点是这次真正的收获：**v66 及以前对所有 stage 的 512×256 纹理都做替换**，
> 这才是"贴图被误替换"的真正来源。加上 stage 门槛后，判据本身就精确了，
> 不需要靠"绑定次数"这种间接信号去猜。

### 2. 安装器体验（用户要求）

- **安装完成后自动退出**：`DestroyWindow` 收尾，不再停在完成窗口上
- **更新说明只保留本版**：删除 V1.02 / V1.03 / V1.03.1 三块历史说明，
  弹窗第一屏直接是 V1.03.2 的更新内容

## 二、顺带修掉的发布缺陷

检查时发现：包内 `02_源码/安装器/setup.c` **一直是 V1.01 的版本串**。
上一轮升版只改了 `setup.rc`（资源版本）和 `info_o2.txt`（说明文案），
漏了 `setup.c` 里的窗口标题与副标题 —— 结果 **V1.03.1 安装器窗口上显示的是 V1.01**。

本版三处已同步为 V1.03.2，并用 UTF-16 检索确认二进制内确实含 `V1.03.2`：

```
V1.03.2  ·  2026-10          → 是
Obscure II 汉化补丁 V1.03.2   → 是
更新内容块数 = 1
```

> 这条已写进 `02_源码/安装器/README.md` 的"改版本号"章节，作为反面案例。

## 四、验证要点

1. 装完确认 `d3d9.dll` md5 与所选方案一致（B=`6326d10c…` / A=`d0295c87…`）
2. 启动后**不应再看到乱码闪现**
3. 日志应出现：

```
[INIT] ===== V69_PROD 即时提升+stage0门槛 =====
[FSTRICT] 绑定提升阈值 = 1 次（O2_PROMOTE_N 可调，0=关闭）
[FSTRICT] 提升 tex=0x... 为字体（stage0 绑定 1 次）
```

4. `[STAT]` 里 `swaps` 应为数千（V1.03 出问题时只有 344）
5. Alt+Tab 切屏 10 次以上，确认不卡、窗口层级正常
