# Obscure II 简体中文汉化补丁 · V1.04 发版说明

> 发布日期：2026-10-28
> 适用：Steam 版《Obscure II》(AppID 254480)
> 定位：**终极版**（N 卡高分辨率贴图问题正式解决）

---

## 一、这一版解决了什么

**NVIDIA 显卡在 1440p/2K 下，浴室等场景的提示贴图不显示 —— 已解决。**

排查历程（供后续维护参考）：

| 阶段 | 假设 | 结论 |
|---|---|---|
| V1.03 系列 | 「贴图被字体替换误杀」 | 部分成立（阈值 1→9 修掉一类），但不是主因 |
| V1.03.3 | 「目标分辨率自适应」 | **证伪**——引擎本来就传 2K，该改动是空操作 |
| v76 | 「options.xml 引号解析 bug 使玩家设置失效」 | 成立且已修，但仍不解决贴图 |
| v78 | 「视口钳制」（2048→1440） | **失败**——引擎 UI 布局死绑视口，钳制导致主界面残缺 |
| v79 | 「读顶点改 y 坐标」 | **有害**——实测误改 2907 次，导致文字变横线/UI 拉扯，已永久退役 |
| DXVK → N 卡 | 「换 Vulkan 转译层绕过」 | 失败（Vulkan 路径同样不显示） |
| DXVK → A 卡 / 原生 A 卡 | 对照实验 | **A 卡原生就能显示** → 问题锁定在 N 卡 D3D9 驱动路径 |
| dgVoodoo2（多种参数组合） | 「换 D3D11 转译层」 | 失败 |
| **D3D9On12** | 「微软官方 D3D9-over-D3D12」 | **✅ 成功** |

**根因（已由日志坐实）**：引擎给 UI 层设置的视口高度会**大于后备缓冲高度**
（实测 1440 vs 1080、2048 vs 1440），N 卡的 D3D9 驱动对超出窗口边界的顶点执行
严格裁剪，导致位于底部 30% 区域的提示贴图被整块裁掉；A 卡驱动对该情形有容错。
把 D3D9 交给微软的 D3D12 后端渲染后，该裁剪路径被完全绕开。

## 二、核心变更

### 1. D3D9On12 自动分流（新增）

```
启动 → 原生 Direct3DCreate9 建临时对象
     → GetAdapterIdentifier(D3DADAPTER_DEFAULT) 取 VendorId
     → VendorId == 0x10DE (NVIDIA)  → 释放临时对象，改走 Direct3DCreate9On12（D3D12 后端）
     → 其它（AMD 0x1002 / Intel 0x8086 / …）→ 保留原生对象，保持 DX9 原生路径
```

- **玩家无需任何设置**，从 Steam 启动同样生效（逻辑在 `d3d9.dll` 里，不依赖环境变量）
- On12 创建失败（老系统 / 无 D3D12）时**自动回落原生路径**，不会让游戏起不来
- 退路：`O2_FORCE_ON12=0` 或 `O2_D3D9ON12=0` 强制回原生 DX9

### 2. 坐标篡改（v79）永久退役

`g_v79On` 默认 0。实测证据：On12 下一局触发 **2907 次**修正
（`vp=1440 > bb=1080` → `y × 0.75`），导致文字变横线、UI 底框拉扯。
`O2_V79=1` 仍可强制打开，仅供技术取证。

### 3. 不变的部分

V1.03.3 的分辨率自适应、字体提升阈值 9、V1.03.2 的 stage0 门槛与严格字体判定、
V1.02 的窗口化防卡死（`pp->Windowed=TRUE` + 无边框）、V1.01 的双字体方案 —— 全部保留。

## 二·补 安装器模块化选项（V1.04 最终形态）

安装界面提供三个互相独立的选择：

| 选项 | 形态 | 默认 | 落地方式 |
|---|---|---|---|
| **渲染模式** | 单选（智能兼容 / 强制原生） | **智能兼容** | 写 `o2_mode.txt` 到游戏目录，代理启动时读取 |
| **宽屏补丁** | 复选框 | ✔ 勾选 | 决定是否释放 `dinput8.dll` + `patches/main.patch` |
| **字体方案** | 单选（A 寒蝉端黑体 / B 寒蝉活楷） | **B** | 决定释放 `d3d9_a.dll` + `datapack_a.delta`，还是 `d3d9.dll` + `datapack.delta` |

> 字体方案用**单选**而不是复选框：两套方案对应不同的字形几何与数据包，**同时装会字形错位**，
> 所以必须二选一。

### 渲染模式 = 按厂商分流（不是按新老卡）

```
VendorId == 0x10DE (NVIDIA)  -> 尝试 Direct3DCreate9On12（D3D12 后端，修复高分辨率贴图）
VendorId == 0x1002 (AMD)     -> 保持原生 DX9（A 卡原生就正常，不干预）
VendorId == 0x8086 (Intel)   -> 保持原生 DX9
N 卡但 On12 创建失败          -> 自动回落原生 DX9（不报错、不改行为）
```

**不做型号白名单**，因此不会误判未来新卡；判断方式是"尝试即判断"。

### 配置优先级

```
环境变量 O2_FORCE_ON12=1/0   >   o2_mode.txt（安装器写入）   >   智能分流
```

之所以用文件而不是环境变量：**环境变量对 Steam 启动无效**（Steam 用自己的环境），
而 `o2_mode.txt` 放在 `d3d9.dll` 同目录，任何启动方式都能读到。

### v87 修掉的一个真实缺陷

`O2_FORCE_ON12` / `O2_D3D9ON12` 此前**从未生效**：这两个变量在 `ui_init()` 里读取，
而 `ui_init()` 只在第一帧 `Present` 才执行，那时 `Direct3DCreate9` 早已完成分流。
v87 新增 `on12_init_once()` 并在 `Direct3DCreate9` 开头调用，三个配置源（环境变量 /
`o2_mode.txt` / 自动）才真正按优先级工作。已用三组对照实测：

| 场景 | 日志 | on12 |
|---|---|---|
| 无配置 | `force=-1` → `检测到 N 卡，自动启用 D3D9On12` | **1** |
| `o2_mode.txt = compat` | `o2_mode.txt = compat -> 强制原生 DX9` | **0** |
| compat + `O2_FORCE_ON12=1` | `环境变量 O2_FORCE_ON12=1 覆盖安装器设定` | **1** |

## 三、已知限制

### Steam 游戏内覆盖层（Overlay）限制

本补丁为修复 N 卡贴图缺失，默认启用 **D3D9On12 转译**（把 D3D9 交给 D3D12 后端渲染）。
该模式下 **Steam 游戏内覆盖层（Overlay / Shift+Tab 面板）无法显示**。

| 情形 | 说明 |
|---|---|
| 需要覆盖层 | 把游戏目录 `o2_mode.txt` 里的 `auto` 改成 `compat`，覆盖层恢复；但 N 卡高分辨率下的提示贴图缺失会重现 |
| A 卡 / Intel 用户 | 默认原生 DX9，覆盖层不受影响 |
| 影响范围 | 覆盖层缺失**不影响**成就解锁、时长统计、云存档同步与汉化文本显示 |
| 电击枪 / 电击器 | **已实测修复** —— 启用 D3D9On12 后可正常使用电击枪（原生 N 卡 DX9 路径下会冻结/崩溃） |
