### 2.6 【已知限制 · 引擎原生】2K 及以上分辨率下部分提示贴图不显示

**症状**：2560x1440 / 4K 下，个别场景（如浴室）的提示贴图不显示；1080p 下正常。

**定性**：**原版引擎自身的 UI 坐标 / 裁剪问题，与汉化补丁无关。**
纯原版（未装本补丁、原版英文包）在同一分辨率下同样不显示该贴图 —— 引擎把该面片
放大到约 1950px 后飞出可视区域，官方没有为高分辨率做适配。

**处置**：
| 做法 | 说明 |
|---|---|
| **用 1920x1080 游玩** | 官方推荐分辨率；全屏元素与提示贴图均正常 |
| 2K 下强制 100% 缩放 | Windows 显示缩放保持 100% 可能改善，不保证（由引擎决定） |
| 复现对照 | `00_工具中台/04_诊断脚本/2_remove_dll.bat`（卸代理）+ `3_control_no_proxy.bat`（关替换）→ 纯原版复现同一现象即可坐实引擎原生 |

**不要**再往「贴图被误替换」方向排查：那是 §2.3 的问题，已由 V1.03.x 的 stage0 门槛
与绑定提升阈值修复；2K 下这张贴图是被引擎裁掉，不是被我们替换。

## 零、先做这一步（否则后面全白费）

任何排查之前，先确认**你测的到底是哪个 DLL**：

```bat
:: ① 指纹（V1.04 方案B = b42417bd2a51ff5d95d3a84970b8a20f）
certutil -hashfile <游戏目录>\d3d9.dll MD5

:: ② 日志首行版本标记
findstr /C:"V65_PROD" /C:"V87_PROD" /C:"V1" <游戏目录>\d3d9proxy.log

:: ③ 关键计数行（没有这行 = 对应代码根本没跑）
findstr /C:"[FIXS]" /C:"[WIN]" /C:"[WD]" <游戏目录>\d3d9proxy.log
```

> **日志通道是刻意保留的**：DLL 运行时会在游戏目录写 `d3d9proxy.log`，没有开关可关。
> 这是唯一的现场信息来源，别为了"干净"去掉它。安装器文案也明确要求玩家反馈时附带此文件。
>
> 2026-10-23 有**两轮排查**就是因为"以为装了新 DLL、其实还是旧的"而方向全错。
> 三样验完再动手，能省一整晚。

## 二、常见根因与处置

### 2.1 Alt+Tab 切屏卡死（V1.02 已修，但可能因配置回退）

**现象**：画面静止，鼠标键盘有响应，桌面被全屏表面占住，任何程序打不开，但后台进程还在。

**判据**：日志最后一条 `[WD] ckpt=PRESENT:2-callOrig f=<某值>`，且 `f` 不再增长
（进程仍在 = 不是崩溃）。

**根因**：全屏独占（`Windowed=FALSE`）下窗口失焦后，引擎不重新获取独占显示模式，
`Present` 无限等待 vblank。`TestCooperativeLevel` 全程健康 —— **设备没丢，只是在等显示**。

**处置**：
1. 确认 `[WIN] 强制窗口化` 这行存在。没有 → 有人把 `pp->Windowed=TRUE` 删了。
2. 确认启动环境里没有 `O2_WIN=0`。
3. 源码位置：`05_hook源码与译文/d3d9proxy_src/d3d9_proxy.c`，搜 `pp->Windowed = TRUE`。

> 顺带澄清三个**错误方向**，别再走：设备丢失（`[GUARD]` 恒为 0）、
> `DrawPrimitiveUP` 重画、纹理裸指针悬空 —— 都与本症状无关。

### 2.2 切屏后窗口永远置顶

**根因**：游戏认为自己还在全屏，会给自己加 `WS_EX_TOPMOST`；
同时 `WS_POPUP` 窗口缺 `WS_EX_APPWINDOW` 时不参与 Alt+Tab 列表。

**处置**：源码里搜 `WS_EX_APPWINDOW`，确认三件事同时存在：
- `WS_EX_APPWINDOW` 加上
- `WS_EX_TOPMOST` / `WS_EX_TOOLWINDOW` 清掉
- `SetWindowPos(HWND_NOTOPMOST, ...)`
- 以及失焦时复查一次（日志会打 `[WIN] 清除 TOPMOST`）

### 2.3 贴图被"吃掉"（V1.03 已修）

**根因**：字体判据是 `512×256 + A8R8G8B8`。游戏的同类规格纹理不止字体
（UI 图、提示图都可能），一旦命中就被换成中文图集。
2026-10-23 实测一局有 **17 个** 512×256 纹理被登记为"字体"。

**确诊**：跑 `4_no_atlas_swap.bat`（`O2_NO_SWAP=1`）。
- 贴图回来了 → 确诊是误判
- 贴图还是没有 → 与替换无关，往渲染路径查

**V1.03 已修**：改为**严格字体判定**——只有"经 `UpdateTexture` 从 512×256 源
上传到 512×256 目标"的纹理才替换（这是字体图集唯一的上传路径），
其余同规格图片原样保留。日志里会看到：

```
[FSTRICT] 严格字体判定 启用（O2_STRICT_FONT=0 关闭）
[FSTRICT] #1 确认字体 dst=0x...（严格集=1）
[FSTRICT] 跳过同规格非字体纹理 tex=0x...（严格集=N）
```

**V1.03.1 补**：严格判据只认出 1 张字体图集，游戏真正在用的另一张被漏掉 → 文字乱码。
加入「绑定次数提升」：宽松集里反复绑定的纹理自动提升为字体。

**V1.03.2 终版**：阈值降到 **1**（首次绑定即提升，消除启动闪现），
并加 **stage==0 门槛**——只有 stage0 才替换（字体图集只出现在 stage0）。
日志关键行：`[FSTRICT] 提升 tex=0x... 为字体（stage0 绑定 1 次）`。

兜底：严格集为空时自动退回旧判据，保证中文不丢。
对照：`O2_STRICT_FONT=0` 强制走旧判据；`O2_PROMOTE_N=0` 关闭提升。
**判断是否正常**：`[STAT]` 里 `swaps` 应为数千（V1.03 出问题时只有 344）。

### 2.4 启动偶发 `0xC0000005 @ ckpt=init`

**特征**：约 2/3 次启动会崩，发生在设备创建之前，重开即好。
**判断**：与本补丁逻辑无关，疑似 Steam overlay（`gameoverlayrenderer.dll`）注入竞态。
**处置**：重开；若频繁，Steam 库里右键游戏 → 属性 → 通用 → 关闭「Steam 界面叠加」再试。

### 2.5 UI 越界纠正开销高

`[FIXS]` 里的 `lock=` 是每帧顶点缓冲读取次数（上限 `O2_FIX_LOCKMAX`，默认 64）。
若某场景明显掉帧且 `lock` 接近上限，把它调低或直接 `O2_FIX_UI_ANY=0`。

> **注意**：V1.02 里这套纠正实际**从未执行**（`seen=0`，视口守卫写错把面片全挡了）。
> 它是死代码，不会有开销，也不会兜底。要启用得先修守卫（见 §三）。

## 四、日志标记速查

| 标记 | 含义 | 正常值 |
|---|---|---|
| `[INIT] ===== V6x_PROD ...` | 版本标记 | 必须有 |
| `[WIN] 强制窗口化` / `无边框窗口` | 窗口化生效 | 各一条 |
| `[WIN] 清除 TOPMOST` | 游戏抢置顶被清掉 | 偶发 |
| `[PRES] 窗口不在前台 -> 跳过 Present` | 切屏保护 | 每次切出 1 条 |
| `[WD] ckpt=... f=...` | 看门狗心跳（1.5s） | `f` 持续增长 |
| `[FIXS] f=.. safe1080=.. seen=.. lock=.. hit=..` | UI 纠正统计（每 250 帧） | 1080p 下 `safe1080` 增长 |
| `[GUARD]` | 设备丢失（TestCooperativeLevel 非 OK） | **0** |
| `[LOSS]` | 丢失/恢复跳变 | **0** |

| `[STALE]` | 纹理指针复用被挡 | 少量正常 |
| `[WARN] 字体纹理登记满(32)` | 登记表满，开始淘汰最旧 | 正常 |

## 五、对照实验法（最有效的一招）

怀疑是代理 DLL 的问题时，**别猜，做对照**：

```bat
00_工具中台\04_诊断脚本\3_control_no_proxy.bat
```

它把 `d3d9.dll` 移走、用系统 d3d9 启动（中文会乱码，属预期）。
同样操作下：
- **不卡/不丢贴图** → 问题在代理 DLL
- **一样卡/一样丢** → 问题在游戏或 Steam，与补丁无关

2026-10-23 就是靠这一招把"卡死是不是我们造成的"一刀切开。
